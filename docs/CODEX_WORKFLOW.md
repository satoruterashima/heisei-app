# HEISEI / Codex開発ワークフロー

更新日: 2026-10-22

## 開発拠点
- コードの正本はGitHub `satoruterashima/heisei-app`。
- Codex Cloudではこのリポジトリを接続し、Issueのブランチ上で作業する。
- Google Driveは補助的な原本置場。DriveをCodexの作業ディレクトリとはみなさない。
- デフォルトブランチ `main` へ直接実装を積み上げず、Pull Requestでレビューして統合する。

## Codex起動時の読み順
1. `AGENTS.md`（共通安全ルール）
2. `README.md` と `docs/index.md`
3. 今回のIssue
4. Issueで指定された `資料/V2/` および `.claude/rules/` の該当箇所
5. 対象コード・関連テスト

## Issue単位の作業
1. 現状・影響範囲の調査。
2. 受入条件・仕様矛盾・権限・データ影響の整理。
3. 必要なテストの設計。
4. 承認範囲の最小実装。
5. 型チェック・対象テスト・必要なビルドを実行。
6. 差分と実行結果を報告。未実施は未実施と書く。

## 禁止と承認ゲート
- 秘密情報の出力・コミット禁止。環境変数の実値を報告しない。
- 無承認の本番デプロイ、DB更新、外部課金、強制的な削除は禁止。
- AIによる正式なアカウント停止を実装しない。AI一時停止は別の権限・監査が必要。
- 未決定事項を推測で確定しない。重要な仕様差分は `docs/decisions/open-questions.md` へ記録。
- 現状監査で挙げられた不整合はテストで確定後、対象Issueとして修正する。

## 報告フォーマット
- Issue / ブランチ / 実施内容
- 変更ファイル
- テスト結果: PASS/FAIL/NOT_RUN、実行コマンド
- リスク・未決定事項
- 外部操作の有無: push、PR、デプロイ、DB変更
- 次の推奨Issue（勝手に続行しない）
