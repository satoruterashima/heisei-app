# HEISEI AI運営基盤の追加要件（草案）

更新: 2026-10-22
状態: DRAFT（正式仕様ではない。実装時の自動処分条件は要承認）

## 基本方式
- 全行動をAIで確認せず、サーバー側のルール判定・頻度制限・セキュリティ指標で疑義を検知する。
- キーワード・URL・連絡先・権限・回数などのルールに該当した事例、およびユーザー通報を監査案件にする。
- 重要度と費用上限に応じて必要な案件だけAIに渡す。単純な回数制限はAIを呼ばずに処理する。
- 投稿・DM・プロフィール・友達申請・コミュニティ・決済・認証・管理操作で共通イベント形式を使用。
- ログは目的別に必要最小限を収集。個別メッセージの本文を無条件でAIに送信しない。保存期限と閲覧権限を分ける。
- テキストのキーワード一致だけで違反を断定せず、誤検知とすり抜け双方をテストする。
- サーバー高負荷への即時防御はレート制限・WAF等で実行し、AIは原因調査・要約・推奨のみを担当する。

## AI一時停止と正式停止の分離
- `active`: 通常利用。
- `ai_suspended`: AIによる可逆的な暫定一時停止。確定処分ではない。
- `suspended`: 運営の人間が決定した正式停止。
- `banned`: 永久的な利用禁止を将来必要に応じて検討（人間専用）。

## 可逆性・異議申し立て
- AIが投稿に対処する場合、原則としてハード削除ではなく一時非表示にする。
- 対処には案件ID、対象、根拠、判断者、ルール/モデルバージョン、時刻、復旧操作を記録する。
- AI一時停止中でも専用の対話窓口を利用でき、利用者の反論と証拠を運営に送付できる。
- 運営が誤判定と判断した場合は即時復旧。処分履歴の正確さは維持する。
- 運営が違反と確定した場合のみ正式なアカウント停止へ移行する。
- ユーザーは正式処分後にも問い合わせ・異議申し立ての道を持つ。
- 異議申し立てを行った事実自体による追加処分は行わず、期間は違反内容と承認済み処分基準に従う。
- AI暫定停止の期限・審査SLA・停止期間・再犯条件は未決定。自動停止実行は承認まで無効とする。

## 権限と安全性
- AIは任意SQL、秘密情報、自由な権限変更・本番設定変更を実行できない。
- 操作は種類を限定した管理API、監査ログ、冪等性、ロールバック手段を必須とする。
- 投稿や対話に含まれるプロンプトインジェクションはデータとして扱い、命令とみなさない。
- 監査ルールの変更、停止、復旧、AI判断にはバージョンを記録。
- 誤判定率、覆された判断、審査時間、AI呼出数・費用、重大事故を継続的に評価する。
- 人間による承認済み事例のみを参照用データとし、AIの過去出力を正解として自己学習させない。

## 未決定

2. 正式停止の違反別期間と再犯条件（会話では「1か月延長」の希望あり）。
3. ルール別の検知閾値、AI自動実行権限、緊急時対応。
4. モデル・プロバイダー、AI費用上限、監査ログ保存期間。
5. 通報者・被通報者の情報開示範囲とプライバシー方針。
