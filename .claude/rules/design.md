# デザインルール

一次情報源は `資料/V2/HEISEI_正式デザイン方針書_v2.0.docx` と `モックアップ/モックアップ/`（本番用UI）。`モックアップ/モックアップ/販促用/` はLP・ストア掲載・広告専用の資料であり、アプリ本体のUI仕様としては採用しない（レビューで実機モックアップとの構成差異が見つかっているため）。

## 1. 採用デザインの結論

アプリ本体は、Deep Tealのヘッダー・白いカード・Neon Pinkのアクセントを用いたUIを正式採用する。カラフルな配色案は正式UIには使わず、**先行登録特典テーマ**専用として扱う。

日常的に使える落ち着きと、レトロデジタルの楽しさを両立させる。運営文言では「平成」「懐かしい」「あの頃」を過度に使わず、機能を自然な現在のサービスとして提示する（`project.md` 1章のトーンルールを参照）。

## 2. カラーパレット

| 役割 | カラー | Hex | 用途 |
|---|---|---|---|
| Primary | Deep Teal | #0C4B63 | ヘッダー、主要導線、信頼感 |
| Secondary | Navy | #1A2E4A | 本文、見出し、アイコン |
| Accent | Neon Pink | #FF2D6F | 投稿、選択、通知、課金導線 |
| Warm Surface | Soft Cream | #FFF6E6 | 特典、注意、温かいカード |
| Base | Light Gray | #F2F4F7 | 画面背景、区切り |
| Surface | White | #FFFFFF | カード、入力欄 |

安全領域（エラー色、警告、フォーカス表示、選択状態の識別性）は着せ替えテーマ適用後も変更不可。

## 3. CSS変数（実装ルール）

```css
--color-primary: #0C4B63;
--color-secondary: #1A2E4A;
--color-accent: #FF2D6F;
--color-surface-warm: #FFF6E6;
--color-bg: #F2F4F7;
--color-surface: #FFFFFF;
--radius-card: 12px;
--space-card: 12px;
```

CSS変数とTheme Tokenで着せ替えを実装し、ビジネスロジックと分離する（`packages/theme`）。

## 5. レイアウト・ナビゲーション（固定仕様）

* スマートフォン優先、コンテンツ幅は最大720px程度。
* 上部ヘッダー：ロゴ（ショートロックアップ）、通知、プロフィール。上部と下部で重複するメニューを置かない。
* **下部ナビゲーションは「ホーム／スレッド／コミュニティ／マイフレ／メニュー」の5項目で固定する。** これ以外の構成（検索・投稿ボタン中心のナビ等）は正式UIとして採用しない。過去に販促用モックアップで異なる5項目構成が使われた実績があるため、新規に画面を作る際は必ずこの5項目に統一すること。
* 主要CTAはNeon Pink。戻る・検索・設定などはNavyの線画アイコン。
* カード間隔は12px以上、タップ領域は44px以上。

## 6. ロゴ使用規定

* 正式ロゴはカセットテープをモチーフにした第3案。ヘッダーでは横型ロゴ、アプリアイコンではカセット部分を中心に使用する。
* ロゴの比率、文字間隔、色を変更しない。過度な影、グラデーション、回転を加えない。最小表示幅は横型120px、シンボル32pxを目安とする。
* ロゴには2種類のロックアップが存在する。用途を明確に分けること。
  * **ショートロックアップ**（カセットアイコン＋"HEISEI"ワードマークのみ、タグラインなし）：アプリ内ヘッダー、通知、favicon等、サービス内で常時表示される箇所。
  * **フルロックアップ**（タグライン「あの頃と、つながるSNS。」付き）：LP、ストア掲載、販促物など、サービス外向けの箇所限定。タグラインが「あの頃」を含み `project.md` のトーンルールに抵触するため、アプリ内では使用しない。

## 7. 主要コンポーネント

| コンポーネント | 仕様 |
|---|---|
| 本日のトレンディ | ホーム上部に2行表示。1989-2006年からランダムな年を1つ選び、その日の同月同日のニュース・事件・芸能・ゲーム・流行を表示（複数の異なる年を同時に並べない） |
| 投稿カード | 141文字、画像不可。アバター、名前、時刻、本文、いいね、コメント、メニュー |
| 注目スレッド | 自然な題名（例：「あの人は今!?」）。残り時間、レス数、kskを表示 |
| コミュニティカード | 自然な名称（例：「アニメ好き集まれ」「音楽好きの部屋」）。レベル、人数、説明 |
| 有料案内 | 広告非表示、メール、ksk、着せ替え等を簡潔に提示 |
| 広告カード | 無料会員のみ。広告表記を明確にし、入力・安全・個別交流画面には出さない |

## 8. 画面別デザイン方針

* ホーム：本日のトレンディ2行 → 注目スレッド → 投稿フィード → 必要に応じて広告。
* スレッド：残り時間とkskを視認しやすくし、本文とレスに集中できる構造。
* コミュニティ：レベル、経験値、イベント、トピック、メンバーを整理。
* マイフレ：申請中・おすすめをタブで分離。メールと交換日記への導線を明確にする。
* 交換日記：便箋のような温かさを出すが、可読性を優先する。
* アイテムショップ：テーマ、アバター、フレーム、背景をカテゴリ表示。購入前プレビュー必須。

## 9. 着せ替えシステム

| 区分 | 変更可能範囲 | 販売 |
|---|---|---|
| UIテーマ | ヘッダー、背景、カード枠、タブ、ボタン | 課金・特典 |
| プロフィールテーマ | 背景、フレーム、バッジ | 課金・報酬 |
| アバター | 服、髪、アクセサリー | 課金・報酬 |
| コミュニティ装飾 | 背景、バナー、限定服 | レベル報酬 |
| 安全領域 | エラー色、警告、入力状態 | 変更不可 |

先行登録特典テーマ（仮称「FIRST WAVE」、カラフルな配色）は先行登録者限定配布とし、正式リリース後の通常販売は行わない方針。配布条件・期限は `project.md` の要確認事項を参照し、確定前にモックアップ等へ具体的な日付を記載しない。

## 10. アクセシビリティ

* 文字と背景のコントラストを確保する。色だけで状態を伝えない。
* 着せ替え後も警告色・フォーカス表示・選択状態の識別性を維持する。
* 動きのある演出は軽減設定（prefers-reduced-motion等）に従う。
* ピクセルアイコンには代替テキストまたはラベルを付ける。
* WCAGを参考に、文字サイズ、コントラスト、キーボード操作、代替テキストを考慮する。

## 11. コンテンツトーン・表現方針（再掲）

* セクション名は「本日のトレンディ」を使用する。
* ノスタルジーを過度に強調せず、いまの会話が中心であることを表現する。
* コアUIに「懐かしい」「エモい」「あの頃」などの言葉は使用しない。
* コミュニティ名は自然で参加しやすい表現にする（`project.md` 1章の良い例／悪い例を参照。デザイン方針書のタイポグラフィ見本文言などデザイン成果物内でも同様に守ること）。
